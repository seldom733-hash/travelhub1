# Navitravel — проверка оставшихся пунктов E2E

Дата: 2026-11-02  
Режим: production `travelhub`, тестовые данные не очищались.

## 1. Cancelled-штраф после начисления — BLOCKED

Проверено:

- settlement можно создать только через `POST /orders/:id/financial-settlement/confirm`;
- после подтверждения доступны только `GET` и `preview`;
- отдельного endpoint для изменения `clientPenaltyStatus` / `supplierPenaltyStatus` нет;
- в UI панель показывает подтверждённый settlement без действия «отменить штраф».

Фактическая причина:

```text
нет операции перехода CONFIRMED/WITHHELD/RECEIVED → WAIVED/CANCELLED
и нет reversal-проводки для уже начисленного штрафа
```

Поэтому сценарий нельзя выполнить вручную без изменения кода. Статус: **BLOCKED**.

## 2. Конкурентное подтверждение Refund — BLOCKED

Проверено:

- Refund API имеет `create → approve → process`;
- в UI refund создаётся одной кнопкой, которая последовательно выполняет create/approve/process;
- отдельной кнопки «подтвердить Refund» нет;
- две параллельные сессии могут конкурировать только за создание, что уже проверено: создан один `RFD-00000025`.

Отдельного конкурентного подтверждения в интерфейсе нет. Статус: **BLOCKED** (нет UI-операции).

## 3. Повторный webhook — BLOCKED

Поиск по backend controllers не нашёл webhook-endpoint для платёжного провайдера. В текущей конфигурации нет внешнего PSP webhook, который можно было бы повторно отправить.

Статус: **BLOCKED** (нет интеграции/точки входа).

## 4. Отели, авиа, круизы, трансферы, страховка, экскурсии — BLOCKED

Фактическое состояние каталога:

```text
11 135 продуктов
все типа TOUR
```

Отдельных продуктов типов HOTEL, FLIGHT, CRUISE, TRANSFER, INSURANCE, EXCURSION нет. Проверить их через витрину и универсальный поиск нельзя.

Статус: **BLOCKED** (нет тестовых продуктов).

## 5. Что уже проверено

- универсальный поиск туров: PASS, `MKT-REQ-00000020`;
- конкурентное создание Refund: PASS, один `RFD-00000025`;
- конкурентный платёж и settlement: PASS;
- роли ADMIN/FINANCE/MANAGER/BUYER: PASS;
- Ledger и денежные остатки: PASS.

## 6. Рекомендации

1. Реализовать отмену уже начисленного штрафа с reversal-проводкой и доплатой/возвратом клиенту.
2. Добавить отдельное UI-действие подтверждения Refund для проверки конкурентности.
3. Добавить webhook-endpoint и идемпотентную обработку повторной доставки.
4. Добавить тестовые продукты остальных типов услуг.
5. После этого повторить только BLOCKED-сценарии, не перепрогоняя весь аудит.
