## 4. Обнаруженные дефекты

### DEF-001 — карточка заявки не показывает поставщика

- Сценарий: базовая заявка MKT-REQ-00000001.
- Ожидание: поставщик `TEST`.
- Факт: в блоке «Поставщик» карточки Request отображается `—`.
- В финансовом реестре поставщик отображается корректно.
- Причина: карточка Request строит поставщика только из `partnerId`, а тестовая заявка его не имеет.
- Статус: OPEN, не исправлено в этой итерации.

### DEF-002 — данные путешественника в Request

- После подачи заявки `travelerCount = 2`, но `RequestTraveler` не созданы.
- Следствие: карточка показывает «0 из 2», конвертация в Order будет заблокирована до заполнения туристов.
- Статус: OPEN, требуется отдельный экран/поток ввода туристов.

## 5. Проверка каналов

### Канал A — публичная витрина

Проверено:
- главная страница открывается;
- каталог туров/отелей отображается;
- карточки содержат название, поставщика, цену и даты;
- переход в карточку услуги работает;
- отображается форма параметров тура и календарь цен.

**Результат: BLOCKED на этапе выбора предложения.**  
Календарь не содержит доступных цен для тестовых дат, поэтому модальное окно с формой путешественника и кнопкой «Подать заявку» не открывается.

Причина: live-цены/доступность внешних поставщиков (KOMPAS/SummerTour) не возвращают предложения для выбранных тестовых дат.  
Скриншот: `reports/demo/e2e-product-modal.png`.

### Канал B — универсальный поиск

Проверено:
- страница поиска открывается;
- форма параметров поиска отображается;
- поиск туров/отелей возвращает каталог.

**Результат: BLOCKED на этапе live-поиска.**  
Поиск авиабилетов через AZAL/AVIASALES завершился без результатов из-за недоступности внешнего источника; проверка подачи заявки из универсального поиска невозможна без live-предложения.

Скриншот: `reports/demo/e2e-search.png`.

## 5. Ограничения и незавершённые сценарии

1. SupplierPayout не выполнен: для тестового поставщика `TEST` не создан `SupplierObligation`, поэтому интерфейс выплат пуст.
2. Booking остался в статусе `NEW` после исполнения Order — требуется отдельный сценарий подтверждения/исполнения брони.
3. Частичные/полные выплаты поставщику, возвраты, штрафы и отмены не выполнены.
4. Универсальный поиск авиабилетов остаётся BLOCKED из-за внешних источников.
5. Роли, конкурентные операции и полная матрица каналов/услуг не завершены.

## 6. Следующий шаг

- Создать `SupplierObligation` для тестового поставщика через штатный Order/Booking flow или выявить дефект его отсутствия.
- Проверить частичную выплату поставщику и обновление `supplierDebt`.
- Проверить исполнение Booking и полную оплату.
- Перейти к отменам, штрафам и возвратам на тестовой сделке.

- тестовый supplier offer / mock-предложение, доступное в календаре;
- подтверждённый тестовый доступ к KOMPAS/SummerTour с доступными датами;
- разрешение на создание тестовой заявки через внутренний интерфейс менеджера для проверки последующих этапов (с пометкой, что канал подачи отличается).

До этого отчёт не может считаться подтверждением полной готовности системы.
