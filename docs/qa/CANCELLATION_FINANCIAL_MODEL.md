# Финансовая модель отмены сделки

## 1. Исходные данные примера

```text
Цена клиенту:        1000
Себестоимость:        800
Ожидаемая маржа:      200

Клиент оплатил:       300
Поставщику оплачено:  250

До отмены:
  долг клиента:       700
  долг поставщику:    550
```

## 2. Главный принцип

Нельзя обнулять долги только потому, что статус стал `CANCELLED`.

Долг — это **незакрытое обязательство**, а не «сумма минус оплата». После отмены обязательство может быть:

- исполнено возвратом;
- закрыто отказом от дальнейших требований;
- заменено штрафом/неустойкой;
- остаться спорным.

Поэтому после отмены нужен отдельный расчёт:

```text
OrderFinancialSettlement
```

Он уже есть в модели и содержит:

- `finalCustomerLiability` — сколько клиент должен после отмены;
- `remainingToPay` — сколько ещё должен клиент;
- `remainingToRefund` — сколько ещё нужно вернуть клиенту;
- `clientPenaltyAmount` — удержанный штраф;
- `supplierPenaltyShare` — штраф/потеря поставщика;
- `annulledUnpaidAmount` — аннулированный неоплаченный остаток.

## 3. Как должно выглядеть в карточке

### До отмены

| Показатель | Значение |
|---|---:|
| Сумма продажи | 1000 |
| Себестоимость | 800 |
| Оплачено клиентом | 300 |
| Долг клиента | 700 |
| Оплачено поставщику | 250 |
| Долг поставщику | 550 |
| Ожидаемая маржа | 200 |

### После отмены, до возвратов

| Показатель | Значение |
|---|---:|
| Сумма продажи | 1000 |
| Себестоимость | 800 |
| Оплачено клиентом | 300 |
| **К возврату клиенту** | **300** |
| **Долг клиента** | **0** |
| Оплачено поставщику | 250 |
| **К возврату от поставщика** | **250** |
| **Долг поставщику** | **0** |
| Статус расчёта | `PENDING_SETTLEMENT` |

То есть долг клиента и поставщику **не 1000/800**, а 0, потому что после отмены обязательство по оплате прекращается. Вместо долга появляется встречное требование — возврат.

### После полного возврата

| Показатель | Значение |
|---|---:|
| Сумма продажи | 1000 |
| Себестоимость | 800 |
| Получено от клиента | 300 |
| Возвращено клиенту | 300 |
| **Чистые деньги от клиента** | **0** |
| Оплачено поставщику | 250 |
| Возвращено поставщиком | 250 |
| **Чистые деньги поставщику** | **0** |
| Долг клиента | 0 |
| Долг поставщику | 0 |
| Текущий доход | 0 |
| Потерянная маржа | 200 |
| Отменённые продажи | 1000 |

Компания не потеряла 1000 или 800. Она потеряла **ожидаемую маржу 200**, потому что сделка не состоялась.

## 4. Формулы

### До отмены

```text
clientDebt = max(0, sales - (clientCaptured - clientRefunded))
supplierDebt = max(0, cost - (supplierPaid - supplierRefunded))
```

### После подтверждённой отмены

```text
clientDebt = settlement.remainingToPay
clientRefundDue = settlement.remainingToRefund
supplierDebt = activeSupplierObligation.remainingAmount
supplierRefundDue = max(0, supplierPaid - supplierRefunded - supplierRetained)
```

Где `supplierRetained` — сумма, которую поставщик оставил себе как штраф/фактическую стоимость.

### После финансового закрытия

```text
clientDebt = 0
clientRefundDue = 0
supplierDebt = 0
supplierRefundDue = 0
financialStatus = FINANCIALLY_SETTLED
```

## 5. Что делать с маржой и KPI

Нужно разделять три разных показателя:

```text
cancelledSalesAmount    = 1000   — сколько продаж отменено
expectedMargin          = 200    — сколько прибыли ожидали
cancellationCost        = 0      — невозвратные расходы/штрафы
lostIncome              = 200    — потеря ожидаемой маржи
```

Если поставщик не вернул 250:

```text
cancelledSalesAmount = 1000
expectedMargin       = 200
cancellationCost     = 250
lostIncome           = 450   (200 недополученной маржи + 250 невозвратных затрат)
```

Либо, если бизнесу понятнее «фактический убыток»:

```text
actualResult = -250
```

Это разные метрики, их нельзя смешивать в одной цифре.

## 6. Что предлагаю изменить в системе

### 6.1 Разделить «долг» и «к возврату»

В карточке показывать отдельно:

- «Долг клиента» — только когда сделка активна;
- «К возврату клиенту» — после отмены;
- «Долг поставщику» — только когда обязательство активно;
- «К возврату от поставщика» — после отмены.

### 6.2 Не считать долг по формуле `sales - paid` после отмены

Для отменённой сделки источник истины — `OrderFinancialSettlement`, а не разница цены и оплат.

### 6.3 Закрывать обязательство поставщика только фактом

Поставщик должен:

- вернуть деньги;
- выдать кредит-ноту;
- подтвердить невозвратный штраф;
- либо обязательство остаётся `OPEN`/спорным.

Нельзя просто обнулить `supplierDebt` при статусе `CANCELLED`.

### 6.4 Заблокировать действия после закрытия

Если:

```text
clientDebt = 0
clientRefundDue = 0
supplierDebt = 0
supplierRefundDue = 0
financialStatus = FINANCIALLY_SETTLED
```

то:

- платежи клиента — disabled;
- платежи поставщику — disabled;
- возвраты — disabled;
- изменение суммы — disabled.

### 6.5 Правило закрытия заказа

Предлагаю:

- `close` разрешён только при `clientDebt=0` и `supplierDebt=0`;
- если есть `remainingToRefund` — заказ нельзя закрыть, пока возврат не подтверждён;
- если есть спорный долг — статус `PROBLEM`, а не `CLOSED`.

## 7. Примеры

### Пример A. Полный возврат

```text
Клиент:      оплатил 300 → вернули 300 → долг 0
Поставщик:   оплатили 250 → вернул 250 → долг 0
Маржа:       ожидали 200 → получили 0 → потеря 200
```

Правильно:

```text
Долг клиента:      0
К возврату клиенту: 0
Долг поставщику:   0
К возврату от поставщика: 0
Потерянная маржа:  200
```

### Пример B. Поставщик не вернул деньги

```text
Клиент:      вернули 300 → долг 0
Поставщик:   оплатили 250, возврата нет → невозвратные 250
```

Правильно:

```text
Долг клиента:      0
Долг поставщику:   0 (обязательство закрыто штрафом)
Cancellation cost: 250
Потерянная маржа:  200
Итоговое отклонение: 450
```

Либо, если поставщик выставил долг:

```text
Долг поставщику:   250
```

Но это должен быть явный факт, а не автоматическая формула.

### Пример C. Удержан штраф клиента 100

```text
Клиент оплатил 300, вернули 200, удержали 100
Поставщик вернул 250
```

Правильно:

```text
Долг клиента:       0
К возврату клиенту: 0
Долг поставщику:    0
Текущий доход:      100 (штраф)
Потерянная маржа:   100 (200 ожидаемой − 100 штрафа)
```

## 8. Что нужно решить

1. Считать ли `lostIncome` как «недополученную маржу» или как полное отклонение от плана?
2. Разрешать ли закрытие заказа с долгом клиента?
3. Разрешать ли закрытие с долгом поставщику?
4. Считать ли невозвращённые деньги поставщику штрафом автоматически или только по документу?
5. Нужен ли отдельный статус `FINANCIALLY_SETTLED`, чтобы блокировать кнопки не по `CANCELLED`, а по факту закрытия денег?

## 10. Принятое правило закрытия

Заказ нельзя закрыть, а бронирование нельзя завершить, если хотя бы одна из величин больше нуля:

```text
clientDebt          — клиент должен нам
supplierDebt        — мы должны поставщику
clientRefundDue     — мы должны вернуть клиенту
supplierRefundDue   — поставщик должен вернуть нам
```

Дополнительно запрещено закрывать/завершать при статусах:

```text
CANCELLATION_REQUESTED
PENDING_SETTLEMENT
PROBLEM
```

Закрытие разрешено только при:

```text
clientDebt = 0
supplierDebt = 0
clientRefundDue = 0
supplierRefundDue = 0
financialStatus ∈ {FINANCIALLY_SETTLED, FINANCIALLY_SETTLED_WITH_PENALTY,
                   FINANCIALLY_SETTLED_FULL_REFUND, FINANCIALLY_SETTLED_NO_CHARGES}
```

Для заявки отдельной команды «закрыть» нет: она становится `CONVERTED`, `REJECTED`, `UNAVAILABLE` или `CANCELLED_BY_CUSTOMER`. Поэтому правило применяется к заказу (`close`) и брони (`complete`), а не к заявке.

## 11. Где учитывается потерянная маржа

Сейчас `lostIncome` рассчитывается в `DealsService` и выводится только в реестре:

```text
KPI «Потери дохода от отмен»
```

В карточке сделки `lostIncome` и `cancelledSalesAmount` не отображаются. Карточка показывает только `expectedIncome` и `currentIncome`.

Для отменённой сделки в карточку нужно добавить блок:

```text
Ожидаемая маржа
Штраф клиента
Штраф поставщика
Потерянная маржа
```

## 12. Уточнение по вопросу 4

Вопрос был о том, можно ли считать невозвращённые поставщиком деньги автоматически убытком и закрывать обязательство, или нужно ждать подтверждающий документ (кредит-ноту, счёт на штраф, акт).

Варианты:

1. Автоматически считать разницу убытком при отмене.
2. Закрывать обязательство только после документа от поставщика.
3. Оставлять обязательство открытым, пока финансы не подтвердят вручную.

Рекомендую вариант 2: без документа обязательство не закрывать.
