# Manual cancellation scenarios with payment schedules

Пример денежных условий:

```text
Сумма продажи клиенту = 1000 AZN
Себестоимость услуги  = 700 AZN
Плановая маржа        = 300 AZN
```

Текущий доход после отмены:

```text
currentIncome = clientPenalty − supplierPenalty
```

## Фактически созданные тестовые сделки

| Сценарий | Сделка | Менеджер | Поставщик | Статус | Текущий доход |
|---|---|---|---|---|---|
| 1 | `00020069` | Diana | Anextour | CLOSED | 0 |
| 2 | `00020070` | Diana | Anextour | CLOSED | 300 |
| 3 | `00020071` | Diana | Anextour | CLOSED | −400 |

Общие данные:

```text
Сумма продажи = 1000 AZN
Себестоимость = 700 AZN
График клиента: 300 до 25.10.2026 + 700 до 01.11.2026
График поставщика: 700; сценарий 2 — срок 01.12.2026, сценарий 3 — 01.11.2026
Детали: MKT-ORD-00020069, MKT-ORD-00020070, MKT-ORD-00020071
```

Сценарий 2:

```text
получено 300
штраф клиенту 300
штраф поставщику 0
currentIncome = 300
```

Сценарий 3:

```text
получено 300
поставщику оплачено 700
штраф клиенту 300
штраф поставщику 700
currentIncome = 300 − 700 = −400
```

В сценарии 3 долг перед поставщиком закрыт явно:
700 AZN списаны как `SUPPLIER_DEBT_WRITE_OFF`, только после этого сделка
закрыта. Без закрытия долга close guard не пропускает закрытие.

---

## Общий порядок до отмены

### 1. Создать заявку

```text
Заявки → Создание заявки
```

Заполнить:

```text
Клиент
Услуга
Дата услуги
Сумма продажи 1000 AZN
Себестоимость 700 AZN
```

### 2. Подтвердить цену и принять у клиента

```text
Заявка → Подтвердить цену
Заявка → Клиент принял
```

### 3. Сконвертировать в заказ

```text
Заявка → Конвертировать в заказ
```

### 4. Создать график оплат клиента

Открыть карточку сделки:

```text
Финансы → Реестр сделок → Сделка
```

Вкладка графика платежей:

```text
График платежей → Добавить этап
```

Пример:

| Этап | Сумма | Срок | Условие |
|---|---:|---|---|
| Первая оплата | 300 AZN | до начала услуги | штраф активируется после первой оплаты |
| Вторая оплата | 700 AZN | позже | при просрочке — клиентский штраф |

Для сценария 1 сроки штрафов ещё не наступили.

### 5. Подтвердить заказ и создать бронь

```text
Заказ → Взять в обработку
Заказ → Подтвердить
Заказ → Ожидать первую оплату
```

При первой оплате:

```text
Платежи → Добавить платёж
```

Сумма 300 AZN, подтвердить платёж.

```text
Заказ → Отправить поставщику
Бронь → Подтвердить
```

### 6. Создать график оплат поставщику

```text
Финансы → Обязательства поставщиков
```

Открыть обязательство по сделке:

```text
SBO-… → График оплаты поставщику
```

Пример:

| Этап | Сумма | Срок |
|---|---:|---|
| Оплата поставщику | 700 AZN | +15 дней после подтверждения брони |

Варианты для сценариев:

```text
Сценарий 1/2 — срок ещё не наступил
Сценарий 3 — срок уже прошёл
```

### 7. Оплатить поставщику — только для сценария 3

```text
Обязательство → Добавить платёж поставщику
```

Сумма 700 AZN, подтвердить.

## Сценарий 1 — клиент отказался до штрафов

Условия:

```text
клиент ещё ничего не оплатил
срок первой оплаты не наступил
срок оплаты поставщику не наступил
```

Действия:

```text
Сделка → Запросить отмену
Причина: CUSTOMER_FAULT
```

В блоке «Штрафы и возвраты»:

```text
Штраф клиенту   = 0
Штраф поставщику = 0
Итоговая ответственность клиента = 0
```

Затем:

```text
Рассчитать → Утвердить
```

Результат:

```text
captured         = 0
refunded         = 0
clientPenalty    = 0
supplierPenalty  = 0
currentIncome    = 0
```

Закрытие разрешено.

---

## Сценарий 2 — есть штраф клиенту, нет штрафа поставщику

Условия:

```text
клиент оплатил первую часть 300 AZN
вторую часть 700 AZN не оплатил
клиент отказался
срок оплаты поставщику ещё не наступил
```

Действия:

1. Создать график клиента: 300 + 700.
2. Оплатить 300 AZN, подтвердить.
3. Вторую оплату не вносить.
4. Не оплачивать поставщику — срок ещё не наступил.
5. Запросить отмену.

В блоке «Штрафы и возвраты»:

```text
Штраф клиенту     = 300
Штраф поставщику  = 0
Итоговая ответственность клиента = 300
```

Разбивка:

```text
penaltyAmount        = 300
platformPenaltyShare = 300
supplierPenaltyShare = 0
```

Затем:

```text
Рассчитать → Утвердить
```

Результат:

```text
captured         = 300
refunded         = 0
clientPenalty    = 300
supplierPenalty  = 0
currentIncome    = 300
```

Клиенту возвращать нечего: 300 удержаны как штраф.

---

## Сценарий 3 — штраф клиенту и штраф от поставщика

Условия:

```text
клиент оплатил 300 AZN
клиент не оплатил 700 AZN
срок оплаты поставщику прошёл
поставщику оплачено 700 AZN
поставщик возврат не делает
```

Действия:

1. Создать график клиента: 300 + 700.
2. Оплатить 300 AZN.
3. Создать график поставщика на 700 AZN со сроком в прошлом.
4. Оплатить поставщику 700 AZN.
5. Запросить отмену.

В блоке «Штрафы и возвраты»:

```text
Штраф клиенту     = 300
Штраф поставщику  = 700
Итоговая ответственность клиента = 300
```

Разбивка:

```text
penaltyAmount        = 1000
platformPenaltyShare = 300
supplierPenaltyShare = 700
```

Затем:

```text
Рассчитать → Утвердить
```

Перед закрытием закрыть долг перед поставщиком:

```text
Финансы → Обязательства поставщиков → Списать долг
Сумма: 700
Причина: поставщик удержал оплату как штраф
```

Только после `SUPPLIER_DEBT_WRITE_OFF` выполнять:

```text
Сделка → Закрыть
```

Результат:

```text
captured         = 300
refunded         = 0
clientPenalty    = 300
supplierPenalty  = 700
currentIncome    = 300 − 700 = −400
```

Отрицательный текущий доход — убыток от отмены.

Если поставщик возвращает часть денег, его штраф уменьшается:

```text
supplierPenalty = supplierPaid − supplierRefunded
currentIncome   = clientPenalty − supplierPenalty
```

---

## Проверка перед закрытием

Для всех сценариев:

```text
clientDebt = 0
clientRefundDue = 0
supplierDebt = 0
pendingRefund = 0
approval = APPROVED
```

После этого:

```text
Сделка → Закрыть
```

## Где вводить данные

| Данные | Экран |
|---|---|
| График клиента | Карточка сделки → График платежей |
| Платежи клиента | Карточка сделки → Платежи клиента / Платежи |
| График поставщика | Финансы → Обязательства поставщиков → График |
| Платёж поставщику | Обязательства поставщиков → Добавить платёж |
| Штрафы и итоговая ответственность | Карточка сделки → Штрафы и возвраты |
| Возврат клиенту | Финансы → Возвраты |
| Закрытие | Карточка сделки → Закрыть |

---

## Важно

Сроки в графике сами по себе не создают штраф автоматически. Штраф
признаётся финансовым сотрудником в блоке «Штрафы и возвраты» по условиям
договора. `currentIncome` после отмены считается как разница признанных
штрафов:

```text
clientPenalty − supplierPenalty
```

Если штраф признан `WAIVED`, он не уменьшает доход.
