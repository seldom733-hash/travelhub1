# Aviasales 403 — диагностика и исправление

Дата: 2026-11-11

## Симптом

`POST https://tickets-api.{host}/search/v2/start` возвращал:

```text
403 access denied
```

на всех трёх gateway, хотя в браузере цены открывались.

## Что выяснилось

Сравнил запрос backend с реальным запросом сайта `www.aviasales.az`.

Реальный запрос содержит:

```http
x-origin-cookie: _asdcp=...; auid=...; marker=direct; _awt=...; aws-waf-token=...; ...
x-aws-waf-token: 0d0a1235-...:...
x-client-type: web
x-web-client: web_desktop
authorization: ""
accept: application/json
```

Backend отправлял только:

```http
x-origin-cookie: _awt=<сгенерированный>
```

Причины 403:

1. `_awt` генерировался с суффиксом из нулей. Текущий `awt-update` на сайте подмешивает fingerprint браузера, поэтому серверный `_awt` не совпадал с ожидаемым.
2. Не отправлялся `x-aws-waf-token`.
3. В `x-origin-cookie` отправлялся только `_awt`, а не полная cookie-строка браузера.

Проверка из контекста самой страницы Aviasales с полной cookie и `x-aws-waf-token` вернула `200` и `search_id`.

## Исправление

`AviasalesHttpService` теперь читает сессию из Chrome по CDP:

```text
AVIASALES_CHROME_CDP_URL
или AZAL_CHROME_CDP_URL
или http://127.0.0.1:9222
```

Из browser context берутся все cookies для:

```text
https://www.aviasales.az/
https://tickets-api.aviasales.com/
```

и отправляются:

```text
x-origin-cookie = полная cookie-строка
x-aws-waf-token = aws-waf-token
```

Сессия кэшируется на 5 минут. При 403 кэш сбрасывается и cookies перечитываются.

Для headless-варианта можно задать:

```text
AVIASALES_ORIGIN_COOKIE=...
AVIASALES_WAF_TOKEN=...
```

## Проверка

```text
GET /supplier/azal/search GYD → IST 2026-11-20
flights = 105
errors  = 0

AZAL       5
AVIASALES 100
```

## Требование к окружению

Нужен Chrome с remote debugging и открытой вкладкой Aviasales:

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 `
  --user-data-dir="C:\Projects\Navitravel\.chrome-aviasales-cdp" `
  https://www.aviasales.az/
```

Окно должно оставаться открытым. Если Chrome закрыт, Aviasales вернёт ошибку чтения CDP-сессии; AZAL использует тот же Chrome.

## Ограничения

- Cookie/WAF-сессия живёт ограниченное время; при истечении нужен повторный проход Cloudflare в браузере.
- `browser.close()` в коде означает отключение CDP-клиента, а не закрытие пользовательского Chrome.
- В лог cookies не пишутся.
