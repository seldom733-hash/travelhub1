## C. Architecture Decisions

### Campaign Authority
- **Owner:** `marketing.*` schema
- **Model:** `Campaign` with lifecycle (DRAFT→SCHEDULED→ACTIVE→PAUSED/COMPLETED/CANCELLED)
- **Scope:** Platform (partnerId=NULL) or Partner (partnerId set)
- **Business code:** MKT-* (generated by IdsService)

### Audience Authority
- **Owner:** `marketing.*` schema
- **Model:** `CampaignAudience` with JSON criteria referencing CRM fields (lifecycle, leadSource, tags)
- **Does NOT store customer data** — references CRM filter criteria
- **Business code:** MKA-* (generated by IdsService)

### Channel Decision
- **DEFERRED** — No EMAIL/SMS/PUSH transport providers exist
- Communication channel remains PLATFORM only
- No fake delivery infrastructure

### Attribution Authority
- **Owner:** `marketing.*` schema
- **Model:** `CampaignAttribution` linking Campaign to CRM entities (CUSTOMER/LEAD/ORDER/BOOKING)
- **Additive reference** — does NOT mutate canonical Order/Booking acquisitionSource
- **Unique constraint:** (campaignId, entityType, entityId) prevents duplicate attribution

### Lifecycle Decision
- **REUSE existing CRM lifecycle** (ACTIVE/LEAD/PROSPECT on PartnerCustomerRelation)
- Marketing does NOT create its own lifecycle states
- CRM is lifecycle authority; Marketing consumes it

### CRM Boundary
- Marketing consumes CRM Customer/PartnerCustomerRelation identity
- Marketing does NOT duplicate customer tables
- Marketing Audience criteria reference CRM fields (lifecycle, leadSource, tags)

### Communication Boundary
- Marketing Campaigns reference Communication domain context
- Marketing does NOT create a second message-history domain
- No outbound email/SMS/push delivery (deferred)

### Basic vs Pro Boundary
- Partner scope enforced server-side via partnerId
- Platform campaigns visible to all authorized staff
- Partner campaigns visible only to owning partner
- No contact disclosure through Marketing endpoints

### Consent/Preference Status
- **DEFERRED** — No consent/preference entity exists
- Marketing domain foundation implemented without pretending consent exists
- Outbound execution explicitly deferred

## E. Schema/Migration

```sql
CREATE SCHEMA "marketing";

CREATE TABLE "marketing"."Campaign" (
  id TEXT PRIMARY KEY,
  code TEXT UNIQUE NOT NULL,
  name TEXT NOT NULL,
  description TEXT,
  objective "marketing"."CampaignObjective",
  status "marketing"."CampaignStatus" DEFAULT 'DRAFT',
  partnerId TEXT,
  startAt TIMESTAMP,
  endAt TIMESTAMP,
  createdById TEXT NOT NULL REFERENCES "security"."User"(id),
  createdAt TIMESTAMP DEFAULT NOW(),
  updatedAt TIMESTAMP,
  version INTEGER DEFAULT 1
);

CREATE TABLE "marketing"."CampaignAudience" (
  id TEXT PRIMARY KEY,
  code TEXT UNIQUE NOT NULL,
  campaignId TEXT NOT NULL REFERENCES "marketing"."Campaign"(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  description TEXT,
  criteria JSONB,
  estimatedCount INTEGER,
  partnerId TEXT,
  createdById TEXT NOT NULL REFERENCES "security"."User"(id),
  createdAt TIMESTAMP DEFAULT NOW(),
  updatedAt TIMESTAMP,
  version INTEGER DEFAULT 1
);

CREATE TABLE "marketing"."CampaignAttribution" (
  id TEXT PRIMARY KEY,
  campaignId TEXT NOT NULL REFERENCES "marketing"."Campaign"(id) ON DELETE CASCADE,
  entityType TEXT NOT NULL,
  entityId TEXT NOT NULL,
  attributionType TEXT DEFAULT 'FIRST_TOUCH',
  attributedAt TIMESTAMP DEFAULT NOW(),
  notes TEXT,
  partnerId TEXT,
  createdById TEXT NOT NULL REFERENCES "security"."User"(id),
  createdAt TIMESTAMP DEFAULT NOW(),
  UNIQUE(campaignId, entityType, entityId)
);
```
