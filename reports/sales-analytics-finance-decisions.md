# Sales Analytics — предлагаемые решения по финансовой методике

Статус: **предложения к FINANCE sign-off**.

## 1. Открытые обязательства

**Решение:** включать `SupplierObligation` со статусом, отличным от `CANCELLED`, включая `OPEN`, в себестоимость.

**Причина:** обязательство уже является начисленным фактом стоимости; ожидание оплаты не должно завышать прибыль.

## 2. Несколько версий obligation

**Решение:** одна последняя версия на `OrderItem`:

```text
orderBy updatedAt desc
```

**Причина:** версии описывают одно обязательство; суммирование версий завышает себестоимость.

## 3. PENDING refunds

**Решение:** включать только `PROCESSED` возвраты.

**Причина:** фактическое движение денег фиксируется processedAt; pending — намерение, а не факт.

## 4. Закрытый заказ без расчёта

**Решение:** не считать финансовый результат закрытым; показывать `MISSING_SETTLEMENT` в reconciliation issues.

**Причина:** нельзя подтвердить окончательную финансовую модель без `OrderFinancialSettlement`.

## 5. Курсовая разница

**Решение:** использовать `aznAmount` из финансового факта; не пересчитывать по курсу на дату отчёта.

**Причина:** аналитика должна сверяться с фактическим учётом, а не с текущим FX.

## 6. Мультисервисный заказ

**Решение:** себестоимость по `OrderItem` из obligation; если obligation по item отсутствует — пропорционально сумме позиции.

**Причина:** сохраняет связь с услугой и не удваивает общий `netSupplierCost`.

## 7. Отменённые заказы

**Решение:** исключать `CANCELLED` из продаж, себестоимости, завершённых и закрытых сделок; оставлять в счётчике отмен.

## 8. Дата финансового события

```text
Payment  → paidAt
Refund   → processedAt
Adjustment → occurredAt
```
